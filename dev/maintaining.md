# Maintainer tasks

Not shipped. Linked from `AGENTS.md`. Script usage is in each script's `--help`.

- **Evals** (the cases in `evals/`, real agent runs, an estimated $5 for all on Sonnet with a Sonnet judge): `dev/run-evals [--case <name>]... [--runs N] [--jobs N] [--out DIR]` (all cases, 4 at once, Sonnet as agent and judge; the Haiku default judge splits its votes). Everything stays in one folder, `~/pmo-eval-runs/<UTC time>/`: `summary.log`, the plugin copy, and per case `eval.log`, `report.html` (the judges' reasons), `aggregate-result.json` and `sandbox-<n>/` (trace, session transcript, the project as the agent left it; never run git inside it). It builds a throwaway plugin copy because the plugin root is `skills/pmo-docs` and `claude plugin eval` needs `evals/` inside the plugin; plain `claude plugin eval` from the repo root never fires the skill. Use Sonnet (Haiku fails 5 of 9). Results are single samples and can flip, so re-run a failing case before changing `SKILL.md`. Prompts pin today's date. Grader lessons: an `llm` grader sees a file's path, not its text; `max: 0` needs `min: 0`; keep grader text short and positive; name output files in the prompt. Bash fails in the eval sandbox (`apply-seccomp ... setgroups`), so the agent cannot run the scripts and graders must not depend on Bash; the agent also runs in `dontAsk` mode, which denies Glob and Grep in the skill folder, so a playbook must name skill files by their exact `${CLAUDE_SKILL_DIR}/...` path.
- **SkillSpector** (before each release): scan a clean copy of the tracked files (a tree with `__pycache__` gives false findings) with `SKILLSPECTOR_PROVIDER=claude_cli SKILLSPECTOR_MODEL=sonnet skillspector scan skills/pmo-docs --baseline dev/skillspector-baseline.yaml`. A real result is SAFE with full coverage and every LLM call succeeded (`llm_calls_succeeded`); a cut-off run is not a result. Haiku reports false positives on the vendored PyYAML. Each LLM call is a `claude` session on the maintainer's plan. Avoid apostrophes in `config.default.yaml` comments (they break the static parser). Every baseline entry needs a reason.
- **Updating vendored PyYAML:** `dev/update-pyyaml <unpacked sdist>` (header has steps; `dev/pyyaml-prune.patch` is the cut; `_vendor/VERSION` is edited by hand).
- **Install check:** `dev/test-install.md`, in a throwaway `CLAUDE_CONFIG_DIR`.
- **Walkthrough check** (before each release): `dev/test-walkthrough.md`, in a throwaway `CLAUDE_CONFIG_DIR`. It runs the walkthrough's commands and the agent prompts; keep it in step with `docs/walkthrough.md`.
