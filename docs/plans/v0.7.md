# 0.7: teams

Status: planned (light packages). Decided with the maintainer on 2026-11-06 (UTC); moved ahead of the format freeze on 2026-11-11 (UTC) so that the freeze covers everything it adds. Hub and settled decisions: [`docs/PLAN.md`](../PLAN.md). Agent rules and the release checklist: hub section 8.

Every earlier version is built for one writer per project and is safe for teams: duplicate ids fail validation, views are deterministic, and the launcher makes a shared hook possible. This version adds the missing pieces: a command that fixes a duplicate id, and documents that two people edit.

---

## 1. Scope

**In**

- **Fixing duplicate ids.** Ids stay `<PREFIX>-<n>`. Two writers who both add `T-14` on two branches get a duplicate after the merge, which validation already rejects. `scripts/renumber.py` fixes it. No format change.
- **An editor per draft.** A draft may carry `editor: <roster slug>` in its front matter. The current writer is named in `pmo/.me`, one roster slug, untracked (setup adds `pmo/.gitignore` with `.me`). Before editing a draft whose `editor` is someone else, the agent says so and asks. No locks.
- **Merge rules, written down.** Registers: one-line entries merge cleanly; a duplicate id is fixed with `renumber.py`. Views: render again. Drafts: a conflict is resolved by hand, then `structure_check`. Finished documents: never merged; a second finished version is a new draft.

**Out**

- Locks, a server, or any network check.

## 4. Work packages

### W1 renumber.py (Sonnet high)

**Goal:** a duplicate id after a merge is fixed with one command and the user's yes on each ambiguous reference (D1).

**Touches:** `skills/pmo-docs/scripts/renumber.py` (new), `tests/test_renumber.py` (new).

**CLI:** `renumber.py <ID> --line FILE:N [--apply] [--rewrite FILE:N]... [--project ROOT]`.

- `--line` names the register line whose entry gets the new id (the user picks which of the duplicates moves; validation prints both lines).
- Without `--apply`: print the new id (next free number for that prefix) and every reference to the old id. Look in other entries' fields across all registers and in draft documents (status `draft`), one line per hit. Finished documents are listed as "left alone", never changed.
- After a merge, a reference to the old id may mean either entry. The script cannot tell, so it rewrites only the lines the user confirmed with `--rewrite`.
- With `--apply`: change the id on the `--line` entry and in each `--rewrite` line, then re-render views. Exit 1 when duplicates remain, 2 on usage errors (an id that is not duplicated, a line that does not hold it).
- Writes only inside `paths.registers`, `paths.documents` (drafts) and `paths.views`; no git commands.

**Tests:** duplicate `T-14` in a temp Acme; the dry run lists the references; `--apply` with one `--rewrite` leaves the others alone; the finished document is unchanged byte for byte; validation passes afterwards; a non-duplicated id exits 2.

**Notes for W3:** `SKILL.md` `allowed-tools` and Scripts table; `track.md`: what to do when validation reports a duplicate id (show both lines, ask which moves, ask per reference); `conventions.md`: flags and exit codes; README: "Two writers" section.

### W2 Editor field (Sonnet high)

**Goal:** a draft can name its editor, and the agent warns before editing someone else's draft (D2).
