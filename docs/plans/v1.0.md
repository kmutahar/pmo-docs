## 1. Scope

**In**

- The config and register formats are declared stable. After 1.0, a breaking change means 2.0.
- Fixing duplicate ids from two writers, without a new format.
- An upgrade test that proves an old project still works.
- `references/conventions.md` is the config reference, and a test keeps it complete.

**Optional**

- Submit the plugin to the Anthropic directory. The requirements are in the hub's Plugin section. The listing icon can only be set at the first developer-portal submission.

## 2. Decisions (settled 2026-11-06)

| # | Topic | Decision |
|---|---|---|
| D1 | Id collisions | Ids stay `<PREFIX>-<n>`. Two writers who both add `T-14` on two branches get a duplicate after the merge, which validation already rejects. `scripts/renumber.py` fixes it: it gives one entry the next free number and rewrites references to it. No format change, so no schema bump and no migration. |
| D2 | Migrations | No 0.x release changes a format (`schema_version` stays 1 through v0.5), so 1.0 ships no migration framework. `conventions.md` documents how `scripts/migrate/NNNN_*.py` would work when the first bump happens. |
| D3 | Upgrade test | A frozen copy of Acme as it was at tag `v0.1.0` (config and registers) must still render, check and audit under 1.0. |
| D4 | Config reference | `references/conventions.md`, written by hand. A test fails when a key in `config.default.yaml` is not named in it. No generator. |
| D5 | After 1.0 | Any change that would make an existing project invalid is `feat!` and waits for 2.0. |

## 4. Work packages

### W1 renumber.py (Sonnet high)

**Goal:** a duplicate id after a merge is fixed with one command and the user's yes on each ambiguous reference (D1).

**Touches:** `skills/pmo-docs/scripts/renumber.py` (new), `tests/test_renumber.py` (new).

**CLI:** `renumber.py <ID> --line FILE:N [--apply] [--rewrite FILE:N]... [--project ROOT]`.

- `--line` names the register line whose entry gets the new id (the user picks which of the duplicates moves; validation prints both lines).
- Without `--apply`: print the new id (next free number for that prefix) and every reference to the old id. Look in other entries' fields across all registers and in draft documents (status `draft`), one line per hit. Finished documents are listed as "left alone", never changed.
- After a merge, a reference to the old id may mean either entry. The script cannot tell, so it rewrites only the lines the user confirmed with `--rewrite`.
- With `--apply`: change the id on the `--line` entry and in each `--rewrite` line, then re-render views. Exit 1 when duplicates remain, 2 on usage errors (an id that is not duplicated, a line that does not hold it).
- Writes only inside `paths.registers`, `paths.documents` (drafts) and `paths.views`; no git commands.

**Tests:** duplicate `T-14` in a temp Acme; the dry run lists the references; `--apply` with one `--rewrite` leaves the others alone; the finished document is unchanged byte for byte; validation passes afterwards; a non-duplicated id exits 2.

**Notes for W4:** `SKILL.md` `allowed-tools` and Scripts table; `track.md`: what to do when validation reports a duplicate id (show both lines, ask which moves, ask per reference); `conventions.md`: flags and exit codes; README: "Two writers" section.

### W2 Upgrade fixture and test (Haiku low)

**Goal:** prove D3.

**Touches:** `tests/fixtures/acme-0.1/` (new: `git archive v0.1.0 examples/acme/pmo` unpacked, config and registers only), `tests/test_upgrade.py` (new).

**Steps:** copy the fixture to a temp folder; run `render_views.py` (exit 0), `render_views.py --check` (exit 0 after the render), and `docs_audit.py` (exit 0: the fixture has no documents, so nothing can be stale). The fixture is never edited; a later release that changes a format adds its own fixture next to it.

**Done when:** the test passes; scrub passes (the fixture is Acme, no real data).

### W3 Config reference test (Sonnet high)

**Goal:** prove D4 and fill the gaps it finds.

**Touches:** `tests/test_conventions.py` (new), `skills/pmo-docs/references/conventions.md` (only the missing keys).

**Steps:** walk `config.default.yaml` to every key path (`paths.documents`, `registers.tasks.blocked`, `doc_types.<type>.when` written once as a pattern, not per type); assert each appears in `conventions.md` in backticks. Add the missing ones to `conventions.md` with their type and default. This is the one package outside the wiring package that may edit `conventions.md`.
