## 4. Work packages

### W1 Source-project trial

**Goal:** the skill runs a real project end to end before anyone else uses it.

**Steps:**
- The maintainer copies the whole source project into a new folder, outside this repo, and creates a throwaway GitHub repo for it (new history, not linked to the source's).
- Replace the copy's own engine files with the skill; keep its config, registers, data, house rules and real overrides. Template and hook paths move to the launcher.
- Run the full flow: validate, render views, audit, draft and finish one document of each kind it uses, translate one.
- Write a report to `tmp/` with counts only: what loaded, what failed, which changes the skill needs. A needed change that breaks a format is allowed (nothing is stable yet); it goes through the maintainer, with tests and a note in the changelog text.
- After any fix, rerun the unit tests, the scrub and the evals the fix touches.

**Done when:** the copy renders and audits clean under the skill, every needed fix is committed with a test, and the maintainer says the trial passed.

### W2 Release 1.0.0

As the hub's release checklist (section 8; the deferred checks ran in the verification release), with `dev/release --dry-run 1.0.0`, plus: the release commit and tag stay local until the maintainer pushes (D2); the install check (`dev/test-install.md`) runs on the 1.0.0 zip, because it is the cheap check of the final tree; the changelog section says the formats are now stable. The maintainer pushes.

### W3 Directory submission (optional, maintainer)

Check the hub's Plugin section requirements against the tree (files under 256 KiB, at most 512 files, no symlinks or binaries). Submit through the developer portal with the icon.
