# 0.8: format freeze

Status: planned. Decided with the maintainer on 2026-11-06 (UTC); reordered on 2026-11-11 (UTC) to come after the teams version and before verification. Hub and settled decisions: [`docs/PLAN.md`](../PLAN.md). Agent rules and the release checklist: hub section 8.

No feature lands here. This version proves the config and register formats hold, writes the stability promise down, and checks the formats against a real project while they can still change.

---

## 1. Scope

**In**

- The config and register formats are declared stable for the first major release. After it, a breaking change means the next major version.
- An upgrade test that proves an old project still works.
- `references/conventions.md` is the config reference, and a test keeps it complete.
- A format smoke test on a copy of the source project: does its data load?

**Out**

- New features and new config keys. A key or format change found by the smoke test is allowed here (nothing is stable until the first major release).

## 2. Decisions

| # | Topic | Decision |
|---|---|---|
| D1 | Migrations | No release changes a format yet (`schema_version` stays 1), so there is no migration framework. `conventions.md` documents how `scripts/migrate/NNNN_*.py` would work when the first bump happens. |
| D2 | Upgrade test | A frozen copy of Acme as it was at tag `v0.1.0` (config and registers) must still render, check and audit. |
| D3 | Config reference | `references/conventions.md`, written by hand. A test fails when a key in `config.default.yaml` is not named in it. No generator. |
| D4 | After the first major release | Any change that would make an existing project invalid is `feat!` and waits for the next major version. |
| D5 | Smoke test | Run on a full copy of the source project that the maintainer makes, kept outside git (under `tmp/source/`). Validation only, no migration, counts only. |

## 4. Work packages

### W1 Upgrade fixture and test (Haiku low)

**Goal:** prove D2.

**Touches:** `tests/fixtures/acme-0.1/` (new: `git archive v0.1.0 examples/acme/pmo` unpacked, config and registers only), `tests/test_upgrade.py` (new).

**Steps:** copy the fixture to a temp folder; run `render_views.py` (exit 0), `render_views.py --check` (exit 0 after the render), and `docs_audit.py` (exit 0: the fixture has no documents, so nothing can be stale). The fixture is never edited; a later release that changes a format adds its own fixture next to it.

**Done when:** the test passes; scrub passes (the fixture is Acme, no real data).

### W2 Config reference test (Sonnet high)

**Goal:** prove D3 and fill the gaps it finds.

**Touches:** `tests/test_conventions.py` (new), `skills/pmo-docs/references/conventions.md` (only the missing keys).

**Steps:** walk `config.default.yaml` to every key path (`paths.documents`, `registers.tasks.blocked`, `doc_types.<type>.when` written once as a pattern, not per type); assert each appears in `conventions.md` in backticks. Add the missing ones to `conventions.md` with their type and default. This is the one package outside the wiring package that may edit `conventions.md`.

### W3 Format smoke test (Sonnet high)

**Goal:** learn how far the source project's registers are from the current formats, before the freeze (D5).

**Touches:** nothing tracked. The report goes to `tmp/format-smoke-test.md` (gitignored).

**Steps:** the maintainer copies the whole source project into `tmp/source/`. Run the validator and `render_views.py --check` on a copy of its registers. Report counts only: entries per register, errors per rule, fields the formats cannot hold. No entry text, names or contact details in the report or the reply; if one slips in, stop and tell the maintainer. Each finding is then decided by the maintainer: change the format now (allowed until the first major release), or leave it for the migration of the source project.

### W4 Docs and wiring (Sonnet high)

`conventions.md` migration section (D1); README "Stability" section (D4); hub decision table: the "Schema version" row says formats are stable from the first major release.

### W5 Release 0.8.0

As the hub's release checklist (section 8; the deferred checks run once, later, in the verification release), plus: the upgrade and config reference tests pass.
