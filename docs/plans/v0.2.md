## 2. Decisions (settled 2026-11-06)

| # | Topic | Decision |
|---|---|---|
| D1 | Generators source | Written fresh from the shipped templates and registers. The source project's generators are not copied. |
| D2 | Generator contract | `generate.py <type> [period] [--week] [--as-of DATE] [--stdout]` reads the winning template (the `where.py` lookup), fills front matter, register-derived tables, counts and the `{{project}}`, `{{manager}}`, `{{period}}`, `{{date}}` placeholders, keeps prose placeholders and HTML comments for the agent, and writes to the `where.py` document path. It refuses when the file exists (exit 3); `--stdout` prints instead. Output is deterministic. A section it fills that is missing from the template is an error (exit 2). |
| D3 | Generator switch | `doc_types.<type>.generator: true` in config. A project sets `generator: null` to go back to agent drafting. |
| D4 | Generator internals | Each generator owns a fixed list of sections, named by heading text, and replaces their bodies; every other section is left exactly as the template has it. Shared helpers live in `pmo_common`: one table writer, one roster lookup, one RAG function. The RAG rule moves from `weekly-status.md` prose into `pmo_common.rag()`, and the playbook points to it. |
| D5 | Which generators | `decision-log`, `team-checklist`, `project-plan`, `status-report`. No snapshots. |
| D6 | Calendar | `project.week_start` (default `monday`; any weekday). A week is labelled with the ISO week of its fourth day (exact ISO for Monday weeks; a Saturday week takes its Tuesday). Config only, no run-time flag; `setup.py` gets `--week-start` because it writes config. |
| D7 | Schema version | Stays `1`. v0.2 adds only optional keys; existing sparse configs keep working. No `feat!`. |
| D8 | Where the commands live | `skills/pmo-docs/skills/init/SKILL.md` and `skills/pmo-docs/skills/publish/SKILL.md`, both `disable-model-invocation: true`. They reach scripts and playbooks through `${CLAUDE_PLUGIN_ROOT}`. W1 verifies they load once; the fallback is `skills/pmo-docs/commands/*.md`. |
| D9 | Publish modes | `publish: { mode: none \| folder \| repo, path, url }`, default `none`. `folder`: a path inside the project; the user commits. `repo`: the top of another local git working tree; after copying, the publish command shows `git status` there and commits only after a second yes; it never pushes. |
| D10 | Publish rules | Only finished documents of a type without `publish: false`. The status vocabulary stays `draft` and `finished`; the source document is never touched. Target = `publish.path` + the document's path under `paths.documents`. A target that exists and differs is a `conflict` and is copied only with `--overwrite <path>` after the user saw the diff and said yes. A stale document is skipped unless the user names it (`--include <path>`). No ledger. `url` only prints links. The publish command grants no `allowed-tools` for `git add` or `commit`, so the permission prompt is a second check. |
| D11 | Publishing outside the command | The main `SKILL.md` still never publishes. Asked to publish, it tells the user to type `/pmo-docs:publish`; in a skill-only install the user runs `publish.py` by hand (README). |
| D12 | Drift warning | A `docs_audit` finding (exit 1) for an override template whose `based_on` is missing, names another type, or has a version below the default's `template_version`. `where.py` prints `drift: yes \| no \| n/a`. A project template with no default of the same file name is exempt (`n/a`). |
| D13 | `release-notes` | One repo per run: the project's own, or `--repo PATH` (any local git working tree; read-only `git -C`). No sub-project concept. Range `--since REF` (default: the previous release notes' `covers_to`, else the first commit of the month) to `--until REF` (default `HEAD`), recorded as `covers_from` and `covers_to` commit SHAs. Sections: New, Improved, Fixed, Breaking changes, Internal, Docs to update, Open questions. A commit links to a task only through an id in its message; any other match is a proposal. Named by month; `generated_from: [tasks, changes]`. |
| D14 | `stakeholder-update` | Sections: Summary, Done, Next, Needs your decision, Risks you should know about, Open questions. Period: month by default, `--week` allowed. `generated_from: [tasks, milestones, risks, issues, decisions, changes]`. Agent-drafted, no generator. |
| D15 | Evals | Add `publish-needs-command`. W14 runs first; if it makes Bash work in the eval sandbox, W5, W6 and W10 each add their eval in the same package. Otherwise generators get no eval. |
| D16 | Status groups in config | New register keys next to `closed`: `registers.tasks.blocked: [blocked]`, `registers.tasks.active: [in-progress]` and `registers.changes.accepted: [approved, implemented]`, so the generators and the RAG rule read status names from config, not constants. Optional keys, so `schema_version` stays 1. |
| D17 | Playbook overrides | A project file `pmo/playbooks/<path>` (new key `paths.playbooks`) replaces `references/<path>` of the same relative path, subfolders included (v0.4 stacks use `stacks/`). Every default playbook gets front matter `playbook_version: 1` before its `Reads:` line; an override records `based_on: <name>@<n>`, where `<name>` is the path without `.md` (`draft`, `stacks/django`). The agent finds the winner by a rule in `SKILL.md` (check `pmo/playbooks/` before reading a playbook), not by a script call; the command skills follow the same rule. `SKILL.md` itself cannot be overridden. Drift for playbooks is reported by `docs_audit` only. |
| D18 | Catalogue | Two optional text keys per doc type, `when` and `regenerate`, filled in `config.default.yaml` for every shipped type. `render_views` writes `pmo/views/catalogue.md`: one row per doc type with title, generated or drafted, when, regenerate, `stale_days`, published or not. Deterministic like every view; `--check` covers it. |

### W3 Shared helpers (Sonnet high)

**Goal:** one home for the table writer, roster lookup, period logic and RAG rule, before any generator is written.

**New functions in `pmo_common.py`** (pure, no printing, no `sys.exit`):

```python
WEEKDAYS = ("monday", "tuesday", "wednesday", "thursday", "friday", "saturday", "sunday")

def week_start(cfg) -> int:
    """0 for Monday ... 6 for Sunday, from project.week_start (default monday). ValueError on an unknown name."""

def week_of(day: datetime.date, start: int) -> str:
    """'YYYY-Www' of the week holding `day`: the ISO week of that week's fourth day."""

def period_range(period: str, start: int) -> tuple[datetime.date, datetime.date]:
    """First and last day (inclusive) of 'YYYY-MM' or 'YYYY-Www'. ValueError for anything else, including a week 53 in a 52-week year."""

def resolve_period(period: str | None, week: bool, as_of: datetime.date, start: int) -> str:
    """The period a command means: the given one (validated, same regex as where.py today), else the week of as_of (week=True), else as_of's month."""

def doc_rel_path(cfg, doc_type: str, period: str, as_of: datetime.date) -> str:
    """'<paths.documents>/<name>' with {title}, {period} and {date} filled, as where.py does today."""

def md_table(headers: list[str], rows: list[list]) -> str:
    """A pipe table: '| a | b |', '|---|---|', one line per row, every cell through cell(). No rows gives one row whose first cell is 'None' and the rest empty (SKILL.md, Empty tables). Ends with a newline."""

def roster_names(root, cfg) -> dict[str, str]:
    """slug -> name from the roster register; {} when there is none."""

def person(value, names: dict[str, str]) -> str:
    """A slug, a list of slugs or free text as display text: slugs become names, other text is kept, lists are joined with ', ', empty is 'not set'."""

def statuses(cfg, register: str, key: str) -> list[str]:
    """registers.<register>.<key> (closed, blocked, active) as a list; [] when absent."""

def rag(cfg, as_of: datetime.date, tasks, milestones=(), issues=(), risks=()) -> tuple[str, str]:
    """(value from vocab.rag, one-line reason). The weekly-status rule:
    red   - a task of the top priority (vocab.priority_order[0]) is blocked or overdue; or a milestone is overdue;
            or three or more tasks are blocked or overdue
    amber - any task is blocked or overdue; or an open issue whose severity is one of the two last values of
            vocab.issue_severity; or an open risk whose impact is the last value of vocab.risk_level;
            or a milestone not closed and due within 7 days after as_of
    green - none of these
    overdue = not closed and due < as_of; blocked = status in registers.tasks.blocked.
    vocab.rag is read by position: [0] green, [1] amber, [2] red.
    The reason names the first rule that matched and up to three ids, e.g. 'top-priority task T-1 is overdue'."""
```

**Changes**

1. `config.default.yaml`, under `registers.tasks`: add `blocked: [blocked]` and `active: [in-progress]` with one comment line: `# blocked and active: statuses that count as blocked and in progress (generators, RAG)`. Add `week_start: monday` under `project` with the comment `# first day of a week: monday to sunday; a week is named by the ISO week of its fourth day`.
2. `render_views.config_errors`: also report `project.week_start` not in `WEEKDAYS`, and a `blocked` or `active` status that is not in the tasks status vocab.
3. `render_views.table(rows, cols)`: keep the `_No entries._` early return for views; build the rest with `pc.md_table(cols, [[r.get(c) for c in cols] for r in rows])`. Views must stay byte-identical.
4. `where.py`: replace its period block and its file-name line with `pc.resolve_period` and `pc.doc_rel_path`. Remove the `shortcut:` comment (W4 makes the week start real). Output unchanged for every current test.
5. `overdue.py`: replace its `table(head, rows)` with `pc.md_table` only if `tests/test_overdue.py` still passes unchanged; otherwise leave it and say so.

**Tests** (`tests/test_pmo_common.py`, new class `Helpers`):

### W5 Generator framework, decision-log, team-checklist (Sonnet high)

**Goal:** `scripts/generate.py` with the shared machinery and the two simplest generators.

**Touches:** `skills/pmo-docs/scripts/generate.py` (new), `skills/pmo-docs/assets/config.default.yaml` (`generator: true` on `decision-log` and `team-checklist`), `tests/test_generate.py` (new), `tests/test_pmo_common.py` (`EveryTool` picks the new script up automatically if it globs `scripts/*.py`; check).

**CLI**

```
python3 generate.py <type> [period] [--week] [--as-of YYYY-MM-DD] [--stdout] [--project ROOT]
```

Exit codes: `0` written (or printed with `--stdout`); `1` register validation failed (nothing written; errors printed as `ERROR ...`, as `render_views` does); `2` usage or config error (unknown type, type with no generator or `generator` not `true`, bad period, template missing a section the generator fills, bad `week_start`); `3` the document already exists (nothing written; message says to edit it, or to delete or rename it to regenerate, and points at `draft.md` step 2).

**Structure of `generate.py`**

```python
GENERATORS = {}  # doc type -> function

def generator(doc_type):
    """Decorator that registers fn(ctx) -> Filled."""

@dataclass
class Ctx:
    root: Path; cfg: dict; doc_type: str; period: str; window: tuple[date, date] | None
    as_of: date; data: dict[str, list[dict]]; names: dict[str, str]

@dataclass
class Filled:
    values: dict[str, str]      # placeholder -> text, applied to front matter and the text before the first '## '
    sections: dict[str, str]    # exact '## ' heading text -> new body (without the heading line)
    slots: dict[str, str]       # exact '## {{...}}' slot heading text -> the generated '## ...' blocks that replace the slot
    notes: list[str]            # printed to stderr as 'note: ...' for the agent to put in Open questions

def fill(template_text: str, filled: Filled) -> str:
    """Apply a Filled to a template. Raises MissingSection(heading) for a section or slot not in the template."""

def main(argv=None) -> int
```

Rules for `fill`:
- Split the body into blocks at lines that start with `## `. The text before the first `## ` is the preamble.
- Placeholders in `values` are replaced in the front matter text and the preamble only (plain string replace of `{{key}}`). Always set: `project` (config `project.name`, or `not set`), `manager` (`project.manager`, through `person`, or `not set`), `period`, `date` (as of, `YYYY-MM-DD`). Front matter keeps `status: draft` and its `checks:` block; `last_updated` becomes the as-of date.
- For a key in `sections`: keep the heading line, keep every line of the old body that is an HTML comment line (starts with `<!--`, through its closing `-->`), drop the rest of the old body, then write the new body. A blank line separates the comments, the body and the next heading.
- For a key in `slots`: replace the whole slot block (heading plus body) with the generated blocks, keeping the slot's comment lines once, before the first generated block. No items: write nothing for the slot (SKILL.md: a repeatable slot with no items is left out).
- Every other block is copied byte for byte.
- Output ends with exactly one newline.

`main` steps: parse args; check the project folder; `cfg = pc.load_config`; check `doc_types[type].generator is True` and `type in GENERATORS`; resolve the period with `pc.resolve_period(..., pc.week_start(cfg))` and the window with `pc.period_range` (None for `{title}`-only names when no period was given: use the as-of month); run `render_views.read_registers` and `render_views.validate` and stop with exit 1 on errors; find the template with `pc.find_asset`; build `Ctx`; call the generator; `fill`; compute the path with `pc.doc_rel_path`; exit 3 if it exists (unless `--stdout`); create the folder; write; print `wrote <path>` and the notes.

Shared selection rules (put them in `generate.py` as small functions, each with a one-line docstring):
- **Tasks of a period** (`period_tasks`): tasks whose `period` equals the month the window ends in. Tasks with no `period` whose `due` falls in the window also count. Tasks with neither: not counted; add a note `N tasks have no period or due date: T-.., T-..` (at most 10 ids, then `and N more`).
- **Sort orders**: tasks by priority (position in `vocab.priority_order`, unknown and empty last), then `due` (empty last), then id number; decisions, risks, issues, changes and milestones by id number; teams by `order`, then `id`. Id number = the integer after the last `-`.
- **Team of a task**: a task's `team` matches a `teams` entry when it equals the entry's `id`, or its `heading` compared case-insensitively. Tasks with no match go under a block headed `No team` with lead `not set`, after the real teams.
- **Empty values**: `not set` for a missing date, owner or priority; `not recorded` for an empty register field (SKILL.md, Empty values).
- **Ids** in backticks where the template has them.

**decision-log generator** (template `assets/templates/decision-log.md`)

### W9 Publish (Sonnet high)

**Goal:** `publish.py`, the publish playbook and the command body.

**Touches:** `skills/pmo-docs/scripts/publish.py` (new), `skills/pmo-docs/references/publish.md` (new), `skills/pmo-docs/skills/publish/SKILL.md` (body), `skills/pmo-docs/assets/config.default.yaml` (`publish:` block and `publish: false` on `docs-audit-report` and `overdue-report`), `skills/pmo-docs/scripts/render_views.py` (`config_errors` for `publish.mode`), `tests/test_publish.py` (new).

**Config**

```yaml
# Publishing: copies finished documents with /pmo-docs:publish only.
# mode: none (default, nothing is published), folder (a folder inside this project) or repo (the top folder of
# another local git repository; the command commits there only after a yes and never pushes).
# path: the target folder, relative to the project root or absolute (repo mode only).
# url: optional web address of the target folder, used only to print links.
publish:
  mode: none
  path: null
  url: null
```

**CLI**

```
python3 publish.py [--apply] [--overwrite REL]... [--include REL]... [--as-of YYYY-MM-DD] [--project ROOT]
```

`REL` is a document path relative to `paths.documents`, as printed in the listing.

**Behaviour**

1. Load config. `mode: none`: print `publish mode is none: set publish.mode and publish.path in pmo/config.yaml` and exit 0.
2. Validate the target (exit 2 with a clear message on any failure):
   - `path` is a non-empty string.
   - `folder`: the resolved path is inside the project, not inside `.git`, not inside `paths.documents` and does not contain it, and is not a symlink out (reuse the `outside` logic: move it from `load_config` to a module-level `pc.outside(root, *parts)` if needed, keeping `load_config`'s behaviour).
   - `repo`: the path exists, is a folder, `git -C <path> rev-parse --show-toplevel` prints the same resolved path, and that top level is not the project's own repository top level.
3. Candidates: every `*.md` under `paths.documents`, sorted, whose front matter has `status: finished` and a `type` that is a doc type without `publish: false`. Drafts and excluded types are counted, not listed.
4. Classify each candidate (target = `<publish path>/<REL>`; check that the target resolves inside the publish path, refuse symlinks out):
   - `stale`: `docs_audit.audit_file` reports a `stale` finding for it.
   - `new`: target missing.
   - `unchanged`: target bytes equal the source bytes.
   - `conflict`: target exists and differs.
   A stale document that is also new or conflicting is listed as `stale`.
5. Print one line per candidate, `<state>: <REL>`, in REL order, then `drafts: N`, `excluded: N`, and with `url` set, `url: <url>/<REL>` under each `new` line.
6. Without `--apply`: write nothing, exit 0.
7. With `--apply`: copy `new`; copy `conflict` only when its REL is in `--overwrite`; copy `stale` only when in `--include` (and, if it also conflicts, also in `--overwrite`). Create folders. Copy bytes (`shutil.copyfile`), never move, never delete. Print `copied: <REL>` for each. Exit 1 when any `conflict` or `stale` was left uncopied, else 0.
8. A `--overwrite` or `--include` naming a REL that is not a candidate: exit 2 before copying anything.
9. The script runs no git command that writes (`test_no_tool_stages_or_commits` must still pass); `rev-parse` only.

**`references/publish.md`** (steps for the agent; read by the publish command)

`Reads:` line: `pmo/config.yaml` (`publish`, `doc_types`), `publish.py` output, `docs_audit.py` output.

1. Run `publish.py` (no `--apply`). With mode `none`, explain the two modes and the config lines, and stop.

3. Show the final list of files to copy and wait for a yes.
4. Run `publish.py --apply` with the agreed `--overwrite` and `--include` flags. Report what was copied and what was left.
5. `folder` mode: say the files are in place and the user commits them when they choose (`references/git.md`). Stop.
6. `repo` mode: run `git -C <path> status --short` and show it. Ask: "Commit these N files in <path>? (no push)". Never push; tell the user the push command. Pre-existing changes in that repo are left alone and mentioned.
