## 1. Scope

**In v0.3**

| Theme | What ships |
|---|---|
| Languages | config `languages:` (draft language, translations, label, direction, glossary path, digits, connectors); per doc type `translate` and `translations`; missing `languages` means English only |
| Translations | a translation is a file next to its original, `<name>.<lang>.md`, with its own front matter keys; `pmo_common` helpers; `where.py --lang` |
| Parity | `scripts/parity_check.py`: a translation matches its original in headings, tables, ids and numbers; `docs_audit` runs it |
| Audit | `docs_audit` finds a translation behind its original; `structure_check` and `publish.py` know translations |
| Playbooks | `references/translate.md` (translate, and bring a translation back in step), `references/intake.md` (chat exports); Finish loops over the translations |
| Glossaries | an approved file per language (read only) and a proposed file next to it (append only) |
| Credential guard | `render_views` validation rejects credential-like strings in any register |
| Generators | `generate.py` exits 2 when the draft language is not English |
| Evals | two new cases, `translation-parity` and `intake-consent`; all twelve run before the release |

**Not in v0.3**

- A chat export parser script: the agent reads the export itself.
- Translating register entries or views: registers hold facts in the language the team wrote them.

## 2. Decisions (settled 2026-11-06)

| # | Topic | Decision |
|---|---|---|
| D1 | Languages config | `languages:` as below. `draft` is the language the documents are written in; `translations` lists the other codes (`[]` = English only). Each code has a block with `label` and `dir` (`ltr` or `rtl`), and optionally `glossary` (a `.md` path inside the project), `digits` (ten characters for 0 to 9), `connectors` (the words for `of`, `to`, `and` between two numbers) and `separators` (characters used as a decimal or thousands mark between digits). A missing `languages` block gives `draft: en`, no translations. Codes match `[a-z]{2,3}` plus an optional `-` and 2 to 8 letters or digits, and are quoted in YAML when YAML would read them as something else (`no`, `on`, `off`). Digits come from config; Python's `unicodedata.decimal` is not used. |
| D2 | Per doc type | `doc_types.<type>.translate: in-period \| after-close` (default `in-period`) says when translation happens. `doc_types.<type>.translations: [codes]` replaces `languages.translations` for that type (`[]` = no translation); the shipped defaults set `translations: []` on `docs-audit-report` and `overdue-report`. |
| D3 | Schema version | Stays `1`. Every key is optional and documents are found the same way. No `feat!`. |
| D4 | Translation file | Next to its original as `<name>.<lang>.md`, for example `2026-03 - Status report.xx.md`. A file is a translation when its front matter has `translation_of`; the file name is a convention that `docs_audit` checks. Front matter is the original's, minus `checks` and `source_hashes`, plus `lang`, `dir`, `translation_of` (the original's path relative to `paths.documents`) and `source_hash`. Templates do not get these keys; the `FORBIDDEN` rule in `tests/test_templates.py` stays. |
| D5 | Source hash | `source_hash` is `pc.body_hash(original text)`: the first 8 hex characters of the SHA-256 of the original's body with front matter, HTML comments, blank lines and trailing spaces removed. Finishing the original, which changes its front matter and removes its comments, does not make a translation behind (a hash of the whole file would). A translation does not copy the original's `source_hashes`. |
| D6 | Audit | `docs_audit` gets two checks: `translation behind` (a finished translation whose `source_hash` differs from `body_hash` of its original) and `parity` (the `parity_check` messages for every translation). Translations are skipped by the register-hash `stale` check and by `old`. A finished original with no translation file is not reported. Front matter rules for translations are in W4. `docs_audit.STALE_CHECKS = ("stale", "translation behind")` is what `publish.py` treats as stale. |
| D7 | Parity | `parity_check.py` compares a translation with its original: same headings in the same order and levels, same tables with the same row and column counts, same ids, same numbers. Each language's digits, connectors and separators come from config. Ids and numbers are compared as lists per section and per table cell, not by position in a sentence. List items and prose wording are not compared (a known limit). |
| D8 | Playbooks | One playbook, `references/translate.md`, covers translating and bringing an outdated translation back in step. No `sync`, no `finalize`. |
| D9 | Glossaries | Approved file at `languages.<code>.glossary`; proposed file next to it, `<glossary stem>.proposed.md`. The agent reads the approved file and only appends to the proposed file. Moving a row from proposed to approved is the user's step. |
| D10 | Finish | Finish loops over the type's translations and reads `translate`. `after-close`: skipped, the reply says translation waits for the period to close. `in-period`: Finish asks once ("Translate into XX now?") because the translation files are beyond the request (`SKILL.md` safety rule 3); on yes it translates and finishes each. A translation is finished only after its original is. |
| D11 | Generators | English only. `generate.py` exits 2 when `languages.draft` is not `en`, with a message to set `generator: null`. |
| D12 | Intake | `references/intake.md`. The agent reads any chat export itself. It proposes entries with `origin: proposed`; entries go in after the user confirms, with `origin: stated`. Done work goes in as `status: done` with its date, after the user confirms and the definition of done is met. The export is never copied into the project. |
| D13 | Credential guard | `render_views` validation rejects credential-like strings in every field of every register (a short regex list, W2). The error names the entry and field, never the text. |
| D14 | Setup | Unchanged. A language is added through `extend.md` ("Change settings"); `setup.py` gets no language flags. |
| D15 | Words | Prose says "original" for the document a translation is made from, because `GLOSSARY.md` already uses Draft for a document that is not finished. The config key stays `languages.draft`; the finding text is "translation behind its original". |
| D16 | Source project | W13, after the release, with no agent work: the maintainer decides whether the source project migrates to the skill or stays separate (hub, "Open decisions"). Migrating would get its own plan. |
| D17 | Evals | Add `translation-parity` and `intake-consent`. Bash is blocked in the eval sandbox unless the eval sandbox Bash check in W12 fixed it, so graders never depend on Bash (follow the grader lessons in `AGENTS.md`). |
| D18 | Release | Explicit version `0.3.0` (hub section 8). |
| D19 | Completion date | Tasks get an optional `done_on` date field (after `due`, in `dates`). Intake writes it for finished work, and `track.md` sets it whenever a task moves to a closed status. `due` keeps meaning the deadline. Optional field, so `schema_version` stays 1. |

Config shape (D1, D2):

def languages(cfg) -> dict:

    """8 hex characters of the SHA-256 of the document body: front matter removed (split_front_matter), HTML comments removed, every line right-stripped, blank lines dropped, lines joined with one newline, UTF-8."""

### W3 parity_check (Sonnet high)

**Goal:** `scripts/parity_check.py`, which says whether a translation matches its original, and the shared test fixture.

**Touches:** `skills/pmo-docs/scripts/parity_check.py` (new), `tests/test_parity_check.py` (new), `tests/translation_fixture.py` (new). `tests/test_pmo_common.py` `EveryTool` should pick the script up if it globs `scripts/*.py`; check, and add it to the list if it does not (one line).

**CLI**

```
python3 parity_check.py [--project ROOT] [FILE ...]
```

`FILE` is a translation. With no file: every document under `paths.documents` whose front matter has `translation_of`. Output, as `structure_check.py`: `ok    <rel>` or `ERROR <rel>: <message>` per file, then `\nN file(s) differ from their originals`. Exit codes: `0` all match or none found; `1` any difference, or a translation that cannot be compared (message says why); `2` usage or a config the skill refuses. A `FILE` that has no `translation_of` is an error line, exit 1.

**Functions**

```python
def normalise(text: str, info: dict) -> str:
    """Digits in info['digits'] become 0-9. Characters in info['separators'] become '.'. A connector word from info['connectors'], or of, to, and, or one of / : - en dash, em dash, between two numbers becomes '~'. Ids are not touched here."""

def id_regex(cfg) -> re.Pattern:
    """Ids from the register prefixes in the config: (?<![A-Za-z0-9])(?:T|P|...)-\\d+ ; the lookbehind, not \\b, so an id glued to a letter of another script still matches."""

def numbers(text: str, info: dict, idrx) -> list[str]:
    """Number phrases in order: ids are removed first, then normalise(), then runs like 2026~03~15, 3~5, 25, 3.5. A percent sign is ignored."""

def compare(original: str, translation: str, info: dict, cfg) -> list[str]:
    """Differences, [] when they match. Uses structure_check.sections and structure_check.tables."""

def check_translation(root, cfg, path) -> list[str]:
    """Reads the translation, finds its original through translation_of (relative to paths.documents), looks up pc.languages(cfg)['info'][lang], and returns compare(...). An unreadable pair gives one message: no translation_of, original missing, lang not in the config, translation_of leaving paths.documents."""
```

`compare` rules (messages name the original's heading text and, for tables, the table number in that section; they print ids and numbers but no prose):

1. Front matter: `type` equal; `period` and `template_version` equal when the original has them.
2. Headings: same count; the same level at each position. When the counts differ, report that and stop comparing sections (they cannot be aligned); still compare tables overall by count.
3. For each aligned section: same number of tables; per table same column count and row count; per cell the number phrases equal (a cell is compared with the same cell in the same row and column); the ids in the section equal as sorted lists; the number phrases of the section's text outside tables equal as sorted lists.
4. Code fences and HTML comments are ignored (as `structure_check.sections` does). A translation whose headings are in another script is fine: headings are compared by level only, never by text.
